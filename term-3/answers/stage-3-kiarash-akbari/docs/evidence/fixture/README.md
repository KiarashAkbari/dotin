# شاهدِ ماشین‌افزار (fixture) — نتیجهٔ چالش نیست

این پوشه خروجی یک اجرای **کامل و واقعی** است: PostgreSQL ۱۶ روی همین ماشین، مهاجرت‌های
`sql/`، بارگذاری از همان حلقهٔ صفحه‌بندی مرحلهٔ ۱، و اجرای `Run All` نوت‌بوک. تنها چیزی که
ساختگی است **داده** است: یک فایل ۱۵۰٬۰۰۰ ردیفی که `tests/fixtures.py` تولید کرد و سرستون
اولش (مثل فایل واقعی Kaggle) خالی گذاشته شد تا قرارداد هدر همان‌طور که هست آزموده شود.

هدف این پوشه فقط یک ادعا است: «خط لوله از سر تا پا روی سرور واقعی کار می‌کند». هیچ‌یک از
عددهایش ادعای کیفیت مدل نیست. در این داده، ستون هدف عملاً از فیچرها مستقل ساخته شده، پس
AUC نزدیک ۰٫۵ و کاهش هزینه نزدیک صفر **انتظار** همین است؛ اگر آن‌جا هم ۰٫۵ و ۰ درصد
نمی‌دیدیم، یعنی معیار دارد چیزی را می‌بیند که وجود ندارد.

## چطور تولید شد

از ریشهٔ مخزن، با venv همان ماشین و یک سرور PostgreSQL محلی:

```bash
# ۰) دادهٔ آزمایشی: همان تولیدکننده‌ای که آزمون‌ها می‌شناسند، با سرستونِ خالیِ فایل واقعی
python scripts/make_fixture.py --rows 150000          # sha256 را چاپ می‌کند؛ از قبل بودن فایل = رد

# ۱) بارگذاری کامل (اسکیما + استیجینگ + خود داده)
PYTHONPATH=src python -m credit.load --reset --config ../stage-1/config/default.toml \
    --credit-config config/credit.toml

# ۲) اجرای نوت‌بوک با همان پایتون، و بعد بازرسی فایل اجراشده
PYTHONPATH=src:../stage-1/src python scripts/run_notebook.py --out solution.executed.ipynb
PYTHONPATH=src:../stage-1/src python scripts/run_notebook.py --check --notebook solution.executed.ipynb
python scripts/build_solution_notebook.py --check --out solution.executed.ipynb
```

## چه چیزی این‌جا هست

| فایل | چیست |
|---|---|
| `run.txt` | خط پایانی اجرا (تعداد سلول‌ها، خطاها، زمان، `problems=`) و خروجی دو بازرسی |
| `credit_evidence.json` | همان فایلی که سلول آخر نوت‌بوک نوشت؛ تنها منبع اعداد `report.md` |
| `credit_run_manifest.json` | manifest بارگذاری: sha256، صفحه‌ها، قرنطینه، digest دیتابیس |
| `report-slots.txt` | پاسخی که `report.apply_to_file` به نوت‌بوک برگرداند |

نوت‌بوک اجراشده در این پوشه کپی نشده است: `../../solution.ipynb` خودش همان فایل
اجراشده است (خروجی‌ها ذخیره شده‌اند) و `python scripts/build_solution_notebook.py` نسخهٔ
تمیزِ بدون خروجیِ همان نوت‌بوک را می‌سازد.

یک نکتهٔ صداقت: اجرای ثبت‌شده با اسکریپتِ موقتیِ همان نشست داده ساخت (همان
`tests/fixtures.write_csv` + خالی‌کردنِ سرستونِ اول)؛ `scripts/make_fixture.py` نسخهٔ
ردگیری‌شده و قابل تکرارِ همان کار است که در مخزن مانده. اگر با آن داده بسازید، sha256 و
پس عددها می‌توانند فرق کنند - sha فایلی که این اجرا واقعاً مصرف کرد در `run.txt` است.

خودتان بردارد.

## بازتولیدِ شاهد بعد از `credit.db`

وقتی ساختِ engine از سه جا به یک تابعِ واحد منتقل شد (`credit.db.engine_for`، با یک probe‌ی
`SELECT 1` و یک `ConfigErrorِ` توضیحی به‌جای tracebackِ راننده)، نوت‌بوک از اول اجرا شد.
`credit_evidence.json` بیت‌به‌بیت همان ماند و فقط `loaded_at` جابه‌جا شد. در manifest هم سه
کلیدِ زمانی فرق کردند و `paging.already_complete_before_run` از `false` به `true` رسید، چون
آن اجرایِ دوباره روی دیتابیسِ از‌قبل‌بارگذاری‌شده بود - پس تفاوت‌ها همگیِ *زمان* و *تاریخچهٔ
بارگذاری*‌اند، نه عددِ مدل. این پوشه دقیقاً برای همین هست: ادعایِ تکرارپذیری با خروجیِ بایگانی‌شده
سنجیده شود، نه با اطمینانِ نویسنده.
