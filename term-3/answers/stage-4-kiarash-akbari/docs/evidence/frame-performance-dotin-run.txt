what produced this file, in one command (run from the answer directory of a clone of
``KiarashAkbari/dotin``, branch ``fix/stage4-live-guards``, with this patchset's files present)::

    python3 docs/evidence/frame-performance-sandbox.py > /tmp/dotin-run-raw.txt 2>&1

The capture is the driver's stdout, unedited below this banner; the banner was added afterwards,
which is the only edit. This is a second capture of one procedure, not a second measurement of one
thing: ``frame-performance-sandbox-run.txt`` beside it is the same script run from the assistant's
mirror repository. Both are kept because the pair is the number that matters -- third bullet.

* the corpus is SYNTHETIC and the machine is the agent sandbox («سندباکس»): 100,000
  generated orders against the shipped schema, views and queries; the row values are invented by
  ``frame-performance-synthetic.py``. No number in this file is a measurement of the project's own
  database, and no number in either file closes checklist 5.3;
* what the run establishes about the *port* is the reason to keep it: the harness, the seeder, the
  external demo and the two live guard modules each executed from
  ``term-3/answers/stage-4-<name>/`` with no path edits, so ``docs/evidence/`` in this tree is a
  working directory and not a copy that
  only runs where it was written. Every step exits 0, the seeder's refusal against a non-empty
  ``olist`` is in section 3, and the guards print ``Ran 84 tests ... OK (skipped=2)`` with the
  URI set, so the skip path is not what ran;
* the two captures of the same procedure, on the same schema with the same row counts, disagree by
  31.2 ms: timed mean 397.7 ms here against 366.5 ms there, whole-frame read 2676.8 ms against
  2463.9 ms. Same plan, same spill (``Hash Batches: 2``, 2938 temp blocks written), same frame of
  97,500 rows x 32 columns with 29 feature columns. That spread is 6% of the 500 ms ceiling,
  produced by nothing but running the thing twice -- which is why the verdict on 5.3 belongs to a
  run on your own server rather than to either file;
* ``tree: KiarashAkbari/dotin @ HEAD f806b29, 8 tracked file(s) differ`` is the truth of the
  moment: ``f806b29`` is patch 0012 of this set, the eight differing files are patch 0013's, and
  ``git am`` rewrites every sha anyway, so the hash is the name of a run and not an address. The
  ``ddl: /tmp/...`` line is a sandbox path on a throwaway clone and nothing else;
* unittest's elapsed-time clause is scrubbed (``in <t>s``) so two runs can be compared byte for
  byte. The measured durations are not scrubbed and will not repeat.
