B.3  What the sandbox run added, that code reading could not
     The first version of the fix was the naive one: `refresh_olist_snapshots()`
     after `lock_connection.commit()`. On the real database it still left all four
     views at 0 rows. The reason is a transaction, not an order: executing the refresh
     reopens a transaction on the lock connection, and the `finally` block closes that
     connection with the transaction still open, so SQLAlchemy rolls the refresh back.
     The committed view is empty again, `ispopulated = t`, exactly the symptom.
     The fix therefore commits after refreshing as well, and `phase0-run-red-green.py`
     was the instrument that showed it. Trace excerpt (red, then the naive fix):

         TRACE refresh done: q1=1 in_tx=True      <- refreshed, but inside an open tx
         FINAL q1 rows: 0                          <- discarded on close

B.4  Limits of B
     PostgreSQL 16.2 rather than the student's 16.x minor, one fixture row per table
     rather than 99k orders, and the pgserver build of postgres, which returns bytes to
     psycopg3 (so the runs use `postgresql+psycopg2`). B proves the mechanism and the
     fix on a real engine; it does not measure anything about the delivery, and it is
     not a substitute for the student's own run of the new tests against `olist_db`.


C. WHAT THIS BASELINE DOES NOT SAY
---------------------------------
* It does not say the `--reset` path is broken for the factory sink: the sink group
  (009 plus `load_stage1_sink`) was skipped in every run above. NOT RUN, marked so.
* It does not say anything about performance. No timing claim appears in this file, and
  none should be inferred from the fact that four `REFRESH` statements now run after the
  commit: the view definitions are unchanged, so the work is the same work that used to
  happen at creation time - except that it now happens against committed data. Measure
  before repeating that as a fact.

  the new test module and of `load-database --reset` against a **disposable** database
