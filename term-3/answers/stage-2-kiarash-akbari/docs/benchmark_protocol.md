# روش ثبت شواهد زمان و پلن

این ابزار نتیجهٔ از پیش آماده را جایگزین کوئری نمی‌کند؛ پنج SELECT زنده را اجرا می‌کند. هنوز نتیجهٔ واقعی benchmark در این سند وجود ندارد.

## پیش‌نیاز

پکیج مرحلهٔ اول باید با تغییرهای همین شاخه نصب شده باشد. PostgreSQL باید با دادهٔ واقعی بارگذاری شده و فایل‌های SQL شمارهٔ ۰۰۱ تا ۰۰۳ اجرا شده باشند. فایل تنظیمات باید بخش database داشته باشد؛ رمز از متغیر محیطی تعیین‌شده در password_env خوانده می‌شود. مسیرهای نسبی config نسبت به پوشهٔ اجرای فرمان هستند.

از پوشهٔ stage-2، پس از نصب editable پکیج stage-1، اجرا کن:

```bash
python -m data_factory.db_benchmark \
  --config ../stage-1-kiarash-akbari/config/default.toml \
  --queries sql/queries \
  --output data/curated/benchmark-baseline.json
```

مسیر config بالا نمونهٔ فایل موجود است؛ ابتدا مقادیر database و مسیر داده‌های آن را برای پوشهٔ اجرای خود بررسی کن. این فرمان دیتابیس یا داده‌ها را ایجاد نمی‌کند.

## تعریف اندازه‌گیری

- دو اجرای گرم‌کردن و هفت اجرای اندازه‌گیری برای هر کوئری، در یک تراکنش read-only با snapshot ثابت.
- زمان کلاینت شامل execute، دریافت دسته‌ای و هش‌کردن نتیجه است؛ این زمان صرفاً زمان سرور نیست.
- همهٔ نمونه‌ها، میانه، صدک ۹۵ به روش nearest-rank و بیشینه ذخیره می‌شوند. با هفت تکرار صدک ۹۵ برابر بیشینه است.
- وضعیت بودجه با بیشینهٔ نمونه‌ها و شرط سخت کمتر از ۲۰۰ms گزارش می‌شود؛ هیچ نمونه‌ای حذف نمی‌شود.
- هش نتیجه و تعداد سطر در همهٔ تکرارها باید ثابت باشد. این بررسی جای تست درستی عددها روی fixture را نمی‌گیرد.
- یک EXPLAIN ANALYZE JSON جداگانه پس از تکرارها ذخیره می‌شود؛ Execution Time آن با زمان کلاینت مخلوط نمی‌شود و یک مشاهدهٔ جداست.
- این آزمایش warm-session است و cache سرد را ادعا نمی‌کند. بار هم‌زمان، سخت‌افزار و وضعیت سرویس را در نوت‌بوک توضیح بده.
- فایل خروجی موجود بازنویسی نمی‌شود؛ برای اجرای بعد مسیر جدید بده.
- برای مقایسهٔ قبل و بعد، فایل پایه را حفظ کن؛ خروجی بهینه‌شده را در فایل دیگر ذخیره و برابری نتیجه‌ها، نوع تغییر و علت تغییر پلن را بررسی کن.

EXPLAIN با سازهٔ کامپایلر SQLAlchemy ساخته می‌شود، نه با جای‌گذاری مقدار پارامتر کاربر. فایل‌های SQL باید فایل‌های مورداعتماد و نسخه‌دار همین پروژه باشند.
